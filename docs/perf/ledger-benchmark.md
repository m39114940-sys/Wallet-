# قياس أداء الدفتر والتخزين (لمدخلات قرار سعة الكتلة)

القرار المعتمد من المالك: **سعة الكتلة 2 MB مقترحة فقط، ولا تُعتمد قبل اختبار حجم المعاملات والأداء.** هذه الوثيقة تسجل قياس Codespace، ولا تكفي وحدها لاعتماد السعة.

## الطريقة

- الأمر: `node scripts/bench-ledger.mjs` (ليس ضمن `npm test`، ويستخدم 2,000 معاملة افتراضياً).
- تُبنى المعاملات الموقّعة أولاً، ثم يُقاس عمل الدفتر وحده.
- البيئة: GitHub Codespace، Linux x86_64، Node.js v24.22.2، Intel Xeon Platinum 8573C، نواتان ظاهرتان، وذاكرة نظام ظاهرة 7.8 GiB. النتائج تتغير باختلاف البيئة والحمل.

## قياس Codespace

شُغّل في 2026-11-23 بالأمر `node scripts/bench-ledger.mjs`:

| القياس | 2,000 معاملة |
|---|---:|
| تطبيق معاملة موقّعة على الدفتر (يشمل التحقق من التوقيع) | 555.5 ms إجمالاً؛ 0.278 ms لكل معاملة |
| إعادة تشغيل من اللقطة (يتحقق من كل توقيع) | 485.3 ms |
| إلحاق سجل بالسجل الإلحاقي مع fsync | 0.878 ms لكل سجل |
| إعادة فتح السجل والتحقق منه | 20.0 ms |
| قراءة سجل عشوائي (200 قراءة) | 0.608 ms لكل قراءة |

أُنشئت المعاملات الموقّعة قبل بدء توقيت تطبيقها. لا يقيس السكربت حجم المعاملة أو مسار الكتلة كاملة.

## ما يعنيه ذلك (بحذر)

- هذا القياس يغطي عمل الدفتر وإلحاق السجل وإعادة فتحه فقط. لا يقيس معالجة كتلة كاملة، أو الشهادات، أو جذر الحالة، أو توقيع التصويت، أو نشرها بين المدققين.
- لا يُستخدم هذا القياس وحده لاعتماد حد لحجم الكتلة؛ يلزم قياس مسار تطبيق كتلة كاملة وقياس على أجهزة المدققين.

## ما لم يُقَس بعد

- مسار الكتلة كاملة (الشهادات، وجذر الحالة، وتوقيع التصويت).
- المعاملات الأخرى مثل معاملات EVM، وحجمها وكلفتها مختلفان.
- أداء الشبكة وتأخير النشر بين المدققين.
- قياس على أجهزة المدققين الحقيقية.

## الخطوة التالية المقترحة

إضافة قياس مستقل يمر عبر مسار تطبيق كتلة كاملة، ثم عرضه على المالك قبل أي قرار بسعة الكتلة.
