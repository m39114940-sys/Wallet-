# تقرير فحص المستودع قبل مرحلة Hybrid PoW + PoS

الفرع: `hybrid-mainnet-foundation` (من `security-hardening` عند `c9ceb5d`).
الغرض: تحديد ما هو منفّذ فعلاً وما هو ناقص قبل أي توسع.

## 1. البنية الحالية

| الطبقة | الملفات | الحالة |
|---|---|---|
| دفتر المحفظة والتوقيع (المتصفح) | `js/ledger.js`, `js/signing.js`, `js/keystore.js`, `js/app.js` | منفّذ، وأُضيف له تحقق صارم في مرحلة سابقة |
| سلسلة الكتل وقواعد الانتقال | `chain/core.js` | منفّذ: كتل مع شهادات اعتماد موزونة، وأدلة توقيع مزدوج، وعقوبات وسجن |
| الأوزان والحصص | `chain/weights.js` | منفّذ بأعداد صحيحة `BigInt`، مع سقف لكل مدقق |
| الإجماع | `chain/consensus.js` | منفّذ: جولات واقتراح وتصويت وقفل وتخطٍّ وإعادة إرسال |
| الاستخراج العشوائي | `chain/vrf.js` | مكتوب ومختبر جزئياً، **غير مطابق لمتجه RFC 9381** ولم يُربط بالإجماع |
| عقدة الشبكة | `node/node.js`, `node/cli.js` | منفّذ: HTTP عبر TLS 1.3 متبادل مع بصمات مثبتة، ومزامنة، وتحديد معدل |
| مفاتيح المدققين | `node/keyfile.js` | مشفّرة بعبارة مرور، بلا HSM |
| أدوات الشبكة | `node/tools.js` | ينشئ Genesis اختبارياً ومفاتيح مدققين |

## 2. ما الذي يحقق متطلبات المواصفة الآن

- **فصل الشبكات**: كل رسالة توقيع مرتبطة بـ`chainId`، والشهادة لسلسلة أخرى تُرفض (`attacks.test.js`). **استثناء معروف**: التحويل الموقّع لا يشمل `chainId`، فيُقبل على سلسلة أخرى لها الحسابات نفسها (موثّق كثغرة 19).
- **الشبكة المتعددة العقد**: أربع عقد عبر HTTPS متبادل تتفق على الكتل، وتتحمل فقد 30% من الرسائل (`lossy.test.js`)، وتعيد إرسال رسائلها.
- **مزامنة عقدة جديدة**: موجودة في `network.test.js`.
- **التعامل مع تعطل المدققين**: موجود ضمن `network.test.js` (يتوقف التقدم دون نصاب، ويستأنف بعد العودة).

## 3. الفجوات بالنسبة للمواصفة

| المتطلب | الحالة |
|---|---|
| Proof of Work | مدمج في قاعدة `hybrid-v1` فقط: كل كتلة تحمل إثباتاً يُتحقق منه في `applyBlock` مقابل الهدف المحسوب من الأسلاف، مع تعديل للصعوبة عند حدود النافذة. لا فصل لدور المعدّن بعد، ولا اختيار سلسلة بأعلى عمل |
| اقتراح الكتل من المعدّنين وفق قاعدة معلنة | **غير منفّذ**، والتصميم في `docs/hybrid-consensus.md` بانتظار الموافقة |
| اختيار السلسلة بأعلى عمل مع حد لإعادة التنظيم | **غير منفّذ** |
| Seed nodes واكتشاف النظراء (Peer Discovery) | **غير منفّذ**. القائمة مغلقة من الإعداد، وهذا متعارض مع المواصفة |
| عقد على أجهزة مستقلة عبر الإنترنت | **غير مُختبر**. يحتاج أجهزة وعناوين عامة لا أملكها |
| ربط المحفظة بالعقد عبر HTTPS بشهادة موثوقة | **غير منفّذ**. يحتاج نطاقاً وشهادة CA عامة |
| اقتصاد: إصدار، مكافآت، رسوم، رهن، حرق | **غير منفّذ**، والتوثيق في `docs/economics-proposal.md` بانتظار قرار المالك |
| Genesis مستقل لـMainnet | **غير منفّذ**، ينتظر التوزيع المعتمد |
| إزالة الصنبور في Mainnet | الصنبور موجود في Genesis الاختباري فقط، ويجب أن يبقى كما هو في Testnet |
| تدقيق أمني مستقل | **غير متاح** من هذه البيئة |

## 4. ملاحظات على الكود تستحق المعالجة

- `chain/vrf.js`: متجه RFC 9381 لا يطابق، وسبب الفرق غير محسوم.
- `chain/core.js`: `TESTNET_FAUCET_UNITS` يُمنح لكل عنوان في Genesis. هذا مقبول للاختبار فقط، ويجب ألا يُنقل إلى أي Genesis رئيسي.
- المُقترِح يُنتج كتلاً فقط عند وجود معاملات معلقة، وهذا مقصود، لكنه يجب أن يُراعى في المراقبة.
- الشبكة الحالية كلها مدققون مغلقون. لا يوجد دور للعقد غير المدققة (relay).

## 5. الخطوة التالية

1. مراجعة `docs/hybrid-consensus.md` والموافقة أو التعديل.
2. مراجعة `docs/economics-proposal.md` وتحديد القيم النهائية، وهي قرار المالك وحده.
3. بعد الموافقة: دمج `chain/pow.js` في قواعد كتل `hybrid-v1` لسلسلة جديدة فقط، دون تغيير قواعد Testnet.

## 6. تحديث: حماية النهائية واختيار السلسلة وحاجز النظراء

- أُضيفت حماية النهائية: لا تُقبل سلسلة تعيد كتابة كتلة مُلتزَم بها.
- اختيار السلسلة في `hybrid-v1` بالعمل التراكمي، مع الإبقاء على القاعدة الطولية في Testnet.
- أُضيف حاجز النظراء الذي يحظر بصمة الشهادة عند تكرار الأخطاء المعرّفة.
- النتيجة: 181 اختباراً ناجحاً، و1 متخطّى (متجه VRF). الاختبارات الجديدة: `forkchoice.test.js` و`guard.test.js`.
- المخاطر المتبقية ومعايير الانتقال إلى Mainnet موثقة في `SECURITY_ARCHITECTURE.md` القسم 7 وما قبله. لا يزال اكتشاف النظراء، وعقد البذور، وتسجيل المدققين، وتدقيق مستقل، واختبار متعدد الأجهزة، والاقتصاد، غير منفذة.
