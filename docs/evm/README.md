# توافق EVM في SmartNode: حالة المراحل

هذا المجلد يتتبع مواصفة "توافق EVM" مرحلةً مرحلةً. الهدف: دعم MetaMask وTrust Wallet وBinance Web3 Wallet دون استبدال محرك SmartNode أو Hybrid PoW+PoS أو قواعد الإجماع أو اقتصاد SNN، وبدون أي نشر على Mainnet. كل ما هنا يخص الـTestnet الجديدة (Chain ID 20261122) فقط، والـTestnet الحالية لم تتغير.

## ما هو منجز في المرحلة D

- `eth_chainId` و`eth_blockNumber` و`eth_gasPrice` و`net_version`.
- `eth_getBalance` و`eth_getTransactionCount` بالوسمين `latest` و`pending`.
- `eth_sendRawTransaction` للتحويلات الموقّعة من نوع legacy بسعر الغاز الثابت للـTestnet.
- `eth_estimateGas` و`eth_call` للتحويلات البسيطة فقط: بلا بيانات استدعاء، وبلا إنشاء عقود.
- `eth_getTransactionReceipt`: إيصالات مشتقة من الكتل المؤكدة، ولا تُخزَّن فيها.

## ما ينقص في المرحلة D

- استدعاء العقود وإنشاؤها، وسجلات الأحداث (logs)، ومعاملات EIP-2718 من النوع المُكتوب.
- قرار المالك بشأن نطاق استدعاء العقود، لأنه يحدد مدى توافق المحافظ.

## ما يمنع الإكمال الآن

1. **قرارات المالك:** الرسوم (توزيع 85/10 مع الحرق، وحدود متحكم الرسوم)، ونسبة PoW/PoS، وطول الحقبة، وتمويل العجز، وتأكيد جدول الهاردفورك (`shanghai` وكلها عند الكتلة صفر).
2. **اختبار الشبكة الحقيقية:** عقد عمليات منفصلة تتبادل المعاملات عبر الشبكة، وهذا لم يُنجز بعد.
3. **تخزين حالة EVM:** الحالة تُعاد بناؤها من الكتل عند كل تشغيل، ولا يوجد تخزين دائم مصمم بعد.
4. **المحافظ الخارجية:** اختبار MetaMask وTrust Wallet وBinance Web3 يحتاج متصفحاً وإضافات وRPC عاماً، وهذا خارج البيئة الحالية.
5. **تعدد الأجهزة:** اختبار توافق المدققين يحتاج أجهزة مستقلة.

## ما لا يُعلن

- لا يُعلن نجاح ربط أي محفظة، لأنه لم يُختبر فعلياً.
- لا يُعلن أن Binance سيدعم العملة، فهذا قرار خارجي لا علاقة له بتوافق المحفظة.
