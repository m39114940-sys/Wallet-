# شبكة SNN الحقيقية: الخطوة الأولى (Phase 1 و Phase 3)

## ما هو حقيقي في هذه الخطوة

- **عمليات منفصلة:** كل عقدة عملية Node مستقلة لها منفذ HTTP ومجلد بيانات خاص بها.
- **اتصال حقيقي:** العقد تتبادل المعاملات والكتل عبر HTTP، وتتزامن عند إعادة التشغيل.
- **توقيعات حقيقية:** كل معاملة موقّعة بـ Ed25519، وكل كتلة موقّعة من منتجها بـ Ed25519.
- **تحقق من كل شيء:** العقدة لا تثق بأي نظير. تُتحقق المعاملات والكتل وجذر Merkle والبصمات والتوقيعات قبل القبول.
- **تخزين دائم:** السلسلة تُكتب إلى القرص بعد كل كتلة، وتُعاد تهيئتها عند التشغيل بالتحقق من بدايتها إلى نهايتها.

## ما ليس حقيقياً بعد (مهم)

1. **منتج واحد للكتل.** عقدة واحدة هي التي تنتج الكتل. هذا يخالف مبدأ المواصفة "لا تجعل خادماً مركزياً يتحكم وحده"، وهو مؤقت حتى يُنفَّذ الإجماع الموزع في Phase 4.
2. **لا يوجد إجماع.** العقد الأخرى تقبل الكتلة الموقّعة من المنتج إذا كانت صحيحة، ولا تتحقق من شهادة نصاب من مدققين متعددين.
3. **HTTP بلا تشفير ولا مصادقة ولا حد لمعدل الطلبات.** مناسب لشبكة محلية أو تجريبية فقط.
4. **المفتاح الخاص للمنتج ملف JSON غير مشفّر** بصلاحيات 600. يجب نقله إلى مخزن آمن قبل أي استخدام حقيقي.
5. **المزامنة تنقل السلسلة كاملة.** مقبول للاختبار، لكنه لن يتحمل سلاسل طويلة.
6. **قاعدة nonce واحدة معلقة لكل مرسل:** المعاملة الثانية من المرسل نفسه تُرفض حتى تُؤكَّد الأولى.
7. **صنبور الاختبار:** كل عنوان في التكوين الأولي يحصل على 100 SNN تجريبية، وهذا لا يملك قيمة.
8. **محفظة الويب لا تتصل بهذه الشبكة بعد.** هي تعمل بسجلها المحلي الخاص.

## التشغيل على جهاز واحد

```bash
# 1. إنشاء ملفات الشبكة: التكوين الأولي ومفتاح المنتج
node node/tools.js init ./net snn-testnet-1 snn1<عنوان-أ> snn1<عنوان-ب>

# 2. المنتج
node node/cli.js --port 8001 --data ./data/producer --genesis ./net/genesis.json --producer-key ./net/producer.json

# 3. تابعان يتصلان بالمنتج
node node/cli.js --port 8002 --data ./data/f1 --genesis ./net/genesis.json --peer http://127.0.0.1:8001
node node/cli.js --port 8003 --data ./data/f2 --genesis ./net/genesis.json --peer http://127.0.0.1:8001

# 4. إنتاج كتلة من المنتج
curl -X POST http://127.0.0.1:8001/produce
```

## النقاط الطرفية

| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/status` | الارتفاع، بصمة الرأس، النظراء، حجم قائمة الانتظار |
| GET | `/blocks?from=n` | الكتل من الارتفاع n |
| GET | `/balance?address=snn1…` | الرصيد بالوحدات الصغرى، والـ nonce التالي |
| POST | `/tx` | إرسال معاملة موقّعة (تُنشر إلى النظراء) |
| POST | `/block` | استلام كتلة من نظير (تُتحقق وتُنشر) |
| POST | `/produce` | إنتاج كتلة من المعاملات المعلقة (المنتج فقط) |
| POST | `/peers` | إضافة نظير `{ "url": "…" }` |
| POST | `/sync` | مزامنة كاملة من نظير `{ "url": "…" }` |

## الاختبارات

`tests/network.test.js` يشغّل ثلاث عمليات حقيقية، ويتحقق من:
- انتشار المعاملة من تابع إلى المنتج، وانتشار الكتلة إلى التابعين.
- رفض إعادة تنفيذ المعاملة (nonce) ورفض معاملة مزوّرة (توقيع).
- رفض كتلة وقّعها مفتاح غير المنتج.
- توقف تابع وإعادة تشغيله، ثم مزامنته الكتلة الفائتة من المنتج.
- رفض كتلة مُعدَّلة في معاملة (جذر Merkle).

`tests/chain.test.js` يختبر قواعد السلسلة وحدها: الترميز الموحّد، وجذر Merkle، وإعادة بناء السلسلة من البداية، ورفض الكتل المزوّرة أو التي تنفق nonce مرتين.

## الخطوات التالية

1. **Phase 4:** استبدال المنتج الواحد بمدققين متعددين، يعتمدون الكتلة بشهادة نصاب من أكثر من ثلثي الوزن، كما في `docs/consensus-design.md`.
2. **اختيار المدققين بالحصص والعقوبات** داخل الشبكة، لا في المحاكاة.
3. **اختيار المنتج بـ VRF** بدل الحساب المعلن.
4. **تشفير الاتصال (TLS) ومصادقة النظراء**، ثم تشغيل العقد على أجهزة مختلفة بعناوين عامة.
5. **تكامل محفظة الويب** مع عقدة حقيقية بدل السجل المحلي.
