# SNN Wallet Web

واجهة ويب لمحفظة **SNN** ضمن مشروع SmartNode Network. هذه نسخة **تجريبية (Testnet)** تعمل بالكامل في المتصفح، ولا تتصل بشبكة حقيقية، ولا تمثل أصولاً ذات قيمة مالية.

## المميزات

- إنشاء محفظة جديدة مع توليد مفتاح خاص عشوائي بـ `crypto.getRandomValues`.
- تشفير المفتاح الخاص بـ **AES-256-GCM** ومفتاح مشتق بـ **PBKDF2-SHA256** (600,000 تكرار). لا يُحفظ أي مفتاح خاص كنص واضح.
- المفتاح الخاص يبقى في الذاكرة طوال الجلسة فقط، ويُطلب فتح المحفظة بكلمة المرور بعد كل تحميل للصفحة.
- عرض الرصيد وعنوان الاستقبال وسجل المعاملات.
- إرسال SNN مع التحقق من العنوان والمبلغ والرصيد.
- حماية من إعادة تنفيذ المعاملة عبر **رقم المعاملة (nonce)** لكل محفظة.
- حساب دقيق بأعداد صحيحة (BigInt) بدقة تصل إلى 0.000001 SNN، فلا تظهر أخطاء الكسور العشرية.
- تصميم داكن يدعم RTL والعربية، ومتجاوب مع الهاتف.
- تنزيل الملف المشفّر للمحفظة كنسخة احتياطية، واستعادتها من الملف بكلمة المرور.
- مراجعة التحويل وتأكيده قبل الإرسال، مع التحقق من العنوان والرصيد أولاً.
- مزامنة التبويبات المفتوحة: التحويلات تظهر في كل تبويب، وحذف المحفظة في تبويب يقفل الباقي.

## التشغيل

لا تحتاج إلى تثبيت أي مكتبة. يلزم فقط Node.js 20 أو أحدث للاختبارات، وPython 3 لتشغيل خادم محلي بسيط.

```bash
# تشغيل الواجهة
npm start            # أو: python3 -m http.server 8080
# ثم افتح http://localhost:8080

# تشغيل الاختبارات
npm test
```

ملاحظة: وحدات JavaScript تُحمَّل كـ ES Modules، لذلك لا تعمل بفتح `index.html` مباشرة من نظام الملفات. استخدم خادماً محلياً كما في الأمر أعلاه.

## الاختبارات

تستخدم الاختبارات `node:test` المدمج في Node.js، دون مكتبات خارجية. تغطي 22 حالة، منها:

- رفض المبالغ السالبة أو بمنازل عشرية زائدة، وتحويل المبالغ إلى وحدات صحيحة بدقة.
- رفض إعادة إرسال معاملة قديمة (replay) ورفض nonce مستقبلي.
- رفض الرصيد غير الكافي دون تغيير الحالة، ورفض التحويل إلى النفس.
- بقاء الحالة بعد تحويلها إلى JSON وإعادة تحميلها دون فقدان دقة.
- فك تشفير المفتاح بالكلمة الصحيحة فقط، ورفض ملف معدّل أو إعدادات KDF ضعيفة.

بالإضافة إلى ذلك، جرى اختبار الواجهة من طرف إلى طرف في Google Chrome (Playwright) بـ 29 فحصاً: 17 لإنشاء المحفظة والإرسال والقفل وفتحها، و12 لمراجعة التحويل وإلغائه، والمزامنة بين تبويبين، والتصدير والاستعادة. إنشاء المحفظة، رفض كلمات المرور الضعيفة، الإرسال وحالات الخطأ، القفل وفتح المحفظة، إعادة التحميل، وعدم وجود أخطاء في الكونسول، وعدم وجود تمرير أفقي على شاشة 390px.

## حدود هذه النسخة (مهم)

هذه نسخة توضيحية ولا يجوز اعتبارها محفظة إنتاجية:

1. **لا توجد شبكة حقيقية.** السجل يعمل محلياً داخل المتصفح (`localStorage`)، وليس Blockchain موزعاً. مرحلة SNN Core (الكتل، Merkle Trees، الإجماع) لم تُنفَّذ بعد.
2. **اشتقاق العنوان ليس Ed25519.** العنوان هو SHA-256 لمفتاح خاص مع نطاق ثابت. المواصفة تشترط Ed25519، وهذا بند مفتوح.
3. **لا توجد توقيعات رقمية.** السجل يتحقق من الـ nonce والرصيد والعناوين، لكنه لا يتحقق من توقيع المرسل. أي كود يعمل في المتصفح يستطيع استدعاء التحويل، لذلك لا تعتمد على هذه الطبقة لأي أمان حقيقي.
4. **صنبور الاختبار (faucet)** يمنح 100 SNN تجريبية عند إنشاء المحفظة. هذا خلق للوحدات من لا شيء، ويجب إزالته قبل أي شبكة عامة.
5. **التخزين محلي لكل متصفح.** لا توجد مزامنة بين الأجهزة. نسخة الاحتياط هي الملف المشفّر الذي يُنزَّل من الواجهة.
6. **لم تُراجَع الواجهة أمنياً** ولم يُجرَ Threat Modeling بعد، كما تشترط المواصفة قبل أي إطلاق عام.

## الخطوات التالية المقترحة

- تنفيذ SNN Core: الكتل بالحقول المطلوبة، Merkle Root، والتحقق من السلسلة كما في المواصفة (Phase 1).
- استبدال الاشتقاق بـ Ed25519 وإضافة التوقيع والتحقق منه (Phase 2).
- نقل السجل إلى خدمة خلفية حقيقية مع P2P ومزامنة العقد (Phase 3 و4).
